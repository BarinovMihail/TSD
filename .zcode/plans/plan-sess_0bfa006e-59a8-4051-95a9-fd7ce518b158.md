## Решение: гибрид `query → path fallback` (только транспорт, UI не трогаем)

В `getCharacteristics` — перебор кандидатов кодирования до первого успеха:

1. **Query-параметр** `GET /invent?Номенклатура=<имя>` — если в имени есть `/` или `\`. На локальной (Apache + правка 1С) проходит `%2F`/`%5C`. На рабочей без правки 1С → 404 → fallback.
2. **Path regular** `GET /invent/<encodeComponent(имя)>` — текущее поведение. Базовый кандидат для позиций без спецсимволов (в этом случае query пропускается ради производительности).
3. **Path double-encoded** (`%2F→%252F`, существующий `_encodeForDecodedRouter`) — на случай сервера, декодирующего `%2F` дважды.

Перебор включается только при HTTP-ошибках маршрута (400/404/500). Сетевые ошибки (timeout/нет связи) уходят в существующий failover `DioClient` по хостам — стратегия при них не переключается.

**Безопасность для рабочей базы (db-srv14, без правки 1С):**
- Позиции без `/` `\` (~99.4%): query пропускается → сразу path regular → идентично текущему поведению.
- Позиции со `/` `\`: query → 404 → path regular → (Apache) 404 → path double-encoded. Результат тот же, что сейчас (не грузится) — **регресса нет**.
